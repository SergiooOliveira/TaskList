# Library (Books & Manga) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Home screen and a themed Library (Books & Manga: shelf, wishlist, series and volume panels, reading actions, book lookup, reading and spending dashboards), plus a one-time Notion import, to the existing Wishlist app.

**Architecture:** One `items` table holds everything (Approach B). `collection` is null for general wishlist items, and `'book'` or `'manga'` for Library items. `bought` means owned. A new `reads` table records reading. Pure functions in `src/lib/` turn rows into the shelf groups and the stats, and React screens render them. Navigation uses hash routes, because GitHub Pages can't rewrite paths. Each screen is themed with a CSS class that sets CSS variables, plus one background component per theme.

**Tech Stack:** Vite, React 19, TypeScript 7, Supabase JS v2, Vitest + Testing Library + jsdom, plain CSS. Google Books API (no key) for lookup.

**Spec:** `docs/superpowers/specs/2026-11-25-library-design.md` (approved). The approved screens are in `docs/superpowers/specs/library-mockups/*.html`. Copy the background SVGs, colours and fonts from those files.

## Global Constraints

- Prices are integer cents in EUR. Format them with the existing `formatEuro`.
- Dates are `YYYY-MM-DD` strings (Postgres `date`). "Today" is the browser's local date.
- Notion CSV dates are **MM/DD/YYYY** (`06/09/2026` = 2026-06-09).
- **Themes:**
  - Home and Wishlist: Emerald Night (the existing tokens).
  - Books: **Nightshade**: bg `#08070A`, text `#E9E1D3`, muted `#A79C88`, accent gold `#CDAA63`, line `#3A3224`. Title in UnifrakturMaguntia, tabs in Cinzel, book text in Cormorant Garamond.
  - Manga: **Higanbana**: bg `#0A0809`, text `#EDE6DC`, muted `#A99E93`, accent `#E0604A`, line `#3A2A26`. Shippori Mincho B1 for headings, Cinzel for tabs.
- The Library header, BOOKS · MANGA tabs, Shelf | Wishlist switch and form chips have **identical size and position** in both themes. The top padding is 64px. Background art sits behind the content (`aria-hidden`, `pointer-events: none`).
- All animation stops under `prefers-reduced-motion`.
- No new runtime dependencies.
- Every new pure function in `src/lib/` gets Vitest tests.
- **Copy (exact):**
  - Switch labels: `Shelf · {n}` / `Wishlist · {n}`.
  - Book actions: `Start`, `Finished`, `Read again`, `Bought`.
  - Volume panel button: `Move {n} to shelf · {price}`.
  - Section headings: `READING NOW`, `SERIES`, `SINGLE BOOKS`.
  - Before-the-app read: `Read before the app`.
- Bottom-sheet panels (series and volumes) use the native `<dialog>` with `showModal()`, like `ItemForm`. They close on ✕, Esc or a backdrop tap without saving.

## Review Focus

1. **Notion CSV quoting.** Titles like `"O ""Mu"" de muichirou"` and a trailing space in `"Alvorecer e Aurora "` must import as `O "Mu" de muichirou` and `Alvorecer e Aurora`. Tested in Task 8.
2. **Start on a book that's already being read** must not open a second read, and **Finished** with no open read does nothing. Tested in Task 1.
3. **Missing pages, price or rating** (null) must count as 0 / be skipped in stats, never `NaN` or `€NaN`. Tested in Task 7.
4. **Google Books failure or empty result** (network error, `totalItems: 0`, no `imageLinks`) shows "No matches. Fill in the details yourself." and leaves the form editable. Tested in Task 6.
5. **Series sorting** with a missing `series_number` puts those books last, A–Z by title, and never crashes. Tested in Task 3.

### Task 3: Library grouping (pure)

**Files:**
- Create: `src/lib/library.ts`, `src/lib/library.test.ts`

**Interfaces:**
- Consumes: `Item`, `Read`, `readState` (Task 1).
- Produces:
  - `type BookGroups = { reading: Item[]; series: SeriesGroup[]; singles: Item[] }`
  - `type SeriesGroup = { name: string; author: string | null; books: Item[]; owned: number; wanted: number; read: number }`
  - `groupBooks(items: Item[], reads: Read[]): BookGroups`
    - Input is the owned and wanted items of one collection.
    - `reading` holds the owned books with state `reading`.
    - A series becomes a group when it has 2 or more items, owned or wanted. Its `books` are sorted by `series_number` ascending, with nulls last and A–Z by title.
    - Groups are sorted A–Z by name.
    - `singles` holds the remaining owned books, A–Z.
    - A reading book that is also in a series appears in both `reading` and its series group.
  - `type MangaSeries = { name: string; author: string | null; owned: Item[]; wanted: Item[]; read: number; range: string }`
  - `groupManga(items: Item[], reads: Read[]): MangaSeries[]`
    - Groups by `series`, falling back to the title when there's no series.
    - `range` is the wanted volume span, like `"14–23"`, or `""` when nothing is wanted.
  - `forms(items: Item[]): string[]` returns the distinct `form` values, matched without regard to case (first spelling kept), sorted.

### Task 8: Notion import

**Files:**
- Create: `scripts/notion-import.mjs`, `scripts/notion-import.test.ts`
- Modify: `README.md` (import steps)

**Interfaces:**
- Produces:
  - `parseCsv(text: string): string[][]`, which follows RFC 4180: quoted fields, `""` escapes, commas and newlines inside quotes, and a BOM is stripped.
  - `mapRow(row: Record<string, string>, coverBase: string | null): { item: Record<string, unknown>; read: Record<string, unknown> | null } | null` returns `null` for rows with an empty title.
  - `toSql(rows: ReturnType<typeof mapRow>[]): string`, which produces one transaction that:
    - inserts the items with `user_id = (select id from auth.users limit 1)`
